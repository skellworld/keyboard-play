# 키보드 놀이 게임 — 요구사항 분석 (v1.1)

> 작성일: 2026-11-21 · 상태: **확정** (열린 질문 6개 결정 완료 → 7장) · v1.1: 스파이크 결과 반영, 고장 대응 기능 삭제

---

## 1. 개요

### 1.1 배경
- 입력이 불안정한(씹힘·연속 입력) **버려질 키보드**를 아이용 장난감으로 재활용한다.
- 아이가 아무 키나 누르면 화면에 그 키에 해당하는 **숫자·알파벳·한글 자모**가 귀엽게 나타난다.
- **갤럭시 태블릿**(USB/블루투스 키보드 연결)과 **Windows PC** 두 환경에서 실행한다.

### 1.2 목표
| # | 목표 | 성공 기준 |
|---|------|-----------|
| G1 | 아이가 키를 누를 때마다 즉각적이고 즐거운 반응 | 키 입력 → 화면 반응 100ms 이내 |
| G2 | 아이가 마구 연타해도 화면이 망가지지 않음 | 연타·동시 입력 폭주 시에도 프레임 유지, 화면 객체 수 상한 유지 |
| G3 | 아이가 게임 밖으로 나가지 못함 | 일반적인 키 연타/화면 터치로 이탈하지 않음 (플랫폼 한계 내에서) |
| G4 | 부모는 쉽게 빠져나올 수 있음 | 안내 문구를 보고 처음 쓰는 부모도 나갈 수 있음 |

### 1.3 사용자
| 사용자 | 특성 | 요구 |
|--------|------|------|
| **아이** (주 사용자, **2~3세**) | **글자를 모름.** 손바닥으로 여러 키를 동시에 누르고 화면을 두드림. 글자보다 그림·소리·움직임에 반응 | 즉각 반응, 아주 큰 글자, 그림, 밝은 색, 소리·읽어주기 |
| **부모** (관리자) | 실행·설정·종료 담당 | 쉬운 시작, 확실한 종료 방법, 아이가 우연히 못 푸는 잠금 |

### 1.4 범위 밖 (이번 버전에서 하지 않음)
- 학습 진도·점수·레벨 같은 "게임성" 요소
- 계정·로그인·클라우드 저장, 광고, 네트워크 통신
- 키보드 하드웨어 자체의 수리나 펌웨어 보정

## 2. 기능 요구사항 (FR)

우선순위: **M** = 필수(MVP), **S** = 있으면 좋음, **C** = 나중에

### 2.1 키 입력 → 화면 표시

| ID | 요구사항 | 우선순위 |
|----|----------|:-------:|
| FR-01 | 숫자 키(상단 숫자열·텐키) → 해당 **숫자**를 화면에 표시 | M |
| FR-02 | 알파벳 키 → 해당 **영문자** 표시 (기본 대문자, 설정으로 소문자) | M |
| FR-03 | 알파벳 키 → **두벌식 배열 기준 한글 자모** 표시 (예: `R`→ㄱ, `K`→ㅏ, `Shift+R`→ㄲ) | M |
| FR-04 | 표시 모드: `숫자+영어` / `숫자+한글` / `영어·한글 함께` 중 부모가 선택. **기본값 `숫자+한글`** | M |
| FR-04a | 한글은 **자모 단독**으로만 표시 (ㄱ, ㅏ …). 연속 입력해도 음절(가)로 조합하지 않음 | M |
| FR-05 | 글자가 아닌 키(Space, Enter, 방향키, F키 등) → 별·하트·비눗방울 같은 **장식 효과** 표시 | M |
| FR-06 | 글자는 **랜덤 위치·랜덤 색**으로 튀어나오는 애니메이션 후 몇 초 뒤 사라짐 | M |
| FR-07 | 키마다 **효과음** 재생 (음량 조절·끄기 가능) | M |
| FR-08 | 글자 **이름 읽어주기** — 기기 내장 음성(TTS). 영어 "에이", 한글 자모 "기역"·"아", 숫자 "일·이·삼" | M |
| FR-08a | 읽어주기는 **새 입력이 오면 이전 음성을 끊고** 새 글자를 읽음 (연타 시 음성이 줄줄이 쌓이지 않게) | M |
| FR-08b | 기기에 한국어/영어 음성이 없으면 읽어주기만 조용히 생략하고 효과음은 유지. 부모 메뉴에 "음성 없음" 표시 | M |
| FR-09 | 글자와 연결된 **이모지 그림** 함께 표시 (예: A → 🍎, ㄱ → 🐻, 3 → 🐥🐥🐥). 그림 세트는 나중에 직접 그린 그림으로 교체할 수 있게 분리 | S |
| FR-10 | 여러 키를 동시에 누르면 각각 표시 (손바닥 연타 대응, 상한은 FR-13·14) | M |

> **설계 결정:** 키 판별은 `event.key`(입력된 문자)가 아니라 **`event.code`(물리 키 위치)**로 한다.
> 이유: 한/영 상태, Windows 한글 IME, 안드로이드의 하드웨어 키보드 언어 설정에 따라 `event.key`는 달라지거나 `Process`로 들어오지만, `event.code`(`KeyR`, `Digit1` …)는 항상 같다. 영문자·한글 자모는 이 물리 위치로부터 직접 매핑한다.

### 2.2 입력 안정화 (아이 연타 대응)

> 스파이크 측정 결과 키보드는 **정상 키보드로 취급**한다 ([03-spike-results.md](03-spike-results.md)). 고장 대응 전용 기능(채터링 필터 FR-12, 멈춘 키 FR-15, 진단 화면 FR-17)은 삭제했다. 아래 항목은 아이가 손바닥으로 연타하거나 키를 꾹 누르는 상황 때문에 유지한다.

| ID | 요구사항 | 우선순위 |
|----|----------|:-------:|
| FR-11 | **키를 꾹 누를 때 생기는 자동 반복**(`event.repeat`)은 무시 → 누른 동안 1회만 표시 | M |
| FR-13 | **전체 속도 제한**: 초당 최대 생성 개수 제한 (기본 10개/초). 넘는 입력은 버림 | M |
| FR-14 | **화면 객체 상한**: 동시에 최대 30개. 넘으면 가장 오래된 것부터 빠르게 사라짐 | M |
| FR-16 | 입력이 씹혀 안 들어온 경우는 별도 처리하지 않음 | — |

### 2.2a 화면 터치 반응

| ID | 요구사항 | 우선순위 |
|----|----------|:-------:|
| FR-18 | 화면을 **터치하면 그 자리에** 비눗방울·별 같은 효과 + 효과음 | M |
| FR-18a | 여러 손가락 동시 터치 각각 반응. 생성 상한은 키 입력과 **공유** (FR-13·14) | M |
| FR-18b | 우측 상단 나가기 영역(FR-30) 안의 터치는 효과를 내지 않음 (나가기 판정 전용) | M |
| FR-18c | 부모 메뉴에서 터치 반응 끄기 가능 (기본 켜짐) | S |

### 2.3 전체화면·이탈 방지 (잠금 모드)

| ID | 요구사항 | 우선순위 |
|----|----------|:-------:|
| FR-20 | 시작 화면의 **"시작" 버튼을 누르면 전체화면 + 잠금 모드** 진입 (브라우저 정책상 사용자 동작이 있어야 전체화면 가능) | M |
| FR-21 | 잠금 모드에서 브라우저 기본 단축키 동작 차단 (새로고침, 뒤로가기, 찾기, 인쇄, Tab 이동 등 `preventDefault`가 가능한 것 전부) | M |
| FR-22 | **Windows: 시스템 키 가로채기** — 지원 브라우저(Chrome·Edge)에서 Keyboard Lock API로 Esc·Alt+Tab·Win 키 등 가능한 범위까지 잠금 | M |
| FR-23 | 터치 오동작 차단: 핀치 줌, 더블탭 줌, 길게 눌러 메뉴, 텍스트 선택, 당겨서 새로고침 방지 | M |
| FR-24 | **안드로이드 뒤로가기**(하드웨어 키보드 Esc 포함) 1차 차단 (history 트릭). 완벽 차단은 불가 → FR-43 앱 고정 안내 | M |
| FR-25 | 전체화면이 **의도치 않게 풀리면**(Esc 길게 누름 등) 놀이 일시정지 + "부모님, 화면을 탭하면 다시 시작해요" 오버레이 | M |
| FR-26 | 화면 꺼짐 방지 (Screen Wake Lock) — 놀이 중 화면이 꺼지지 않도록 | S |

### 2.4 부모용 나가기

| ID | 요구사항 | 우선순위 |
|----|----------|:-------:|
| FR-30 | **터치 나가기**: 화면 **우측 상단 모서리**(약 80×80px)를 **3초 이상** 누름 | M |
| FR-31 | **키보드 나가기**: **Ctrl + Alt + P를 3초 이상** 누름 | M |
| FR-32 | 두 방법은 **양쪽 플랫폼 모두에서** 동작 (태블릿+키보드에서도 Ctrl+Alt+P, 터치스크린 PC에서도 모서리) | M |
| FR-33 | 누르는 동안 **진행 링**을 보여줘 부모가 제대로 누르고 있는지 알 수 있게 함 (1초 지나서부터 표시 → 아이가 우연히 눌렀을 때 눈에 덜 띔) | M |
| FR-34 | 키보드 나가기 판정 중 창 포커스를 잃으면(blur) 누름 상태를 초기화 (떼는 이벤트를 못 받아 "누른 채"로 남는 것 방지) | M |
| FR-35 | 나가기 성공 → 전체화면 해제 + **부모 메뉴** 표시 (다시 시작 / 설정 / 종료 안내) | M |
| FR-36 | 나가기 오작동 방지 **2단계 확인**: 3초 유지 후 화면 임의 위치(나가기 모서리와 겹치지 않게)에 뜨는 "나가기" 버튼을 5초 안에 탭해야 확정. 시간 초과 시 놀이로 복귀. **Enter 확인은 Ctrl+Alt+P로 나가기를 했을 때만** 허용(모서리 터치였다면 버튼만), 자동반복 Enter 무시, 확인 화면이 뜬 뒤 **0.5초 동안의 입력은 무시** (아이가 마구 누르던 손이 그대로 닿는 것 방지) | M |

> 웹 앱은 브라우저 탭 자체를 스스로 닫을 수 없으므로 "나가기"는 **잠금 해제 + 부모 메뉴 표시**를 뜻한다.

## 4. 플랫폼 제약 분석 (가장 중요한 리스크)

"다른 키 입력 방지"는 **웹 브라우저가 할 수 있는 데까지만** 가능하다. 운영체제 수준의 키는 앱이 막을 수 없거나, 막으려면 별도 장치가 필요하다.

### 4.1 Windows (Chrome·Edge)

| 키 | 웹에서 차단 가능? | 비고 |
|----|:----:|------|
| F5, Ctrl+R, Ctrl+W 외 대부분의 브라우저 단축키 | ✅ (전체화면 + Keyboard Lock 시) | 일부 브라우저 단축키는 Keyboard Lock 없이는 못 막음 |
| Esc | ⚠️ | **실측 확인:** Keyboard Lock 중 짧게 누르면 막힘, **약 1.5초 길게 누르면 전체화면 해제** (보안상 변경 불가) → FR-25로 대응 |
| Alt+Tab | ✅ | **실측 확인:** Keyboard Lock으로 막힘 (Chrome 157) |
| Win 키 | ❓ | 미확인 → 7단계 실기기 검증 |
| Ctrl+Alt+Del, Win+L | ❌ | 운영체제 보안 키, 어떤 앱도 차단 불가 |

**더 강하게 막으려면** (선택): Electron/Tauri 같은 데스크톱 앱으로 감싸 키오스크 모드로 실행하거나, Windows "할당된 액세스(키오스크)" 기능 사용. → MVP 이후 검토

### 4.2 갤럭시 태블릿 (Android Chrome + 하드웨어 키보드)

| 항목 | 웹에서 차단 가능? | 비고 |
|------|:----:|------|
| 글자·숫자 키 입력 받기 | ✅ | 입력창에 포커스를 두지 않으면 삼성 키보드(소프트 키보드)가 뜨지 않음 |
| 뒤로가기 / 키보드의 Esc | ⚠️ | history 트릭으로 1차 차단 가능, 완벽하진 않음 |
| 홈, 최근 앱, 알림창 내리기, 키보드의 앱 전환 단축키 | ❌ | 웹·일반 앱 모두 차단 불가 |
| Keyboard Lock API | ❌ | 안드로이드 미지원 |

**해결책**: 안드로이드 기본 기능 **"앱 고정(화면 고정)"**을 부모가 켜고 실행하도록 안내 (FR-43). 앱 고정 중에는 홈·최근 앱으로 나가지 못하고, 해제하려면 뒤로+최근 앱 동시 누름 + 잠금 해제가 필요하다. 이 경우 게임 내 "나가기"는 게임 잠금을 풀고, 앱 고정 해제는 부모가 따로 한다.

### 4.3 공통 브라우저 정책
- 전체화면·소리 재생은 **사용자 동작(탭/클릭) 후에만** 가능 → "시작" 버튼이 반드시 필요 (FR-20)
- 읽어주기(TTS) 한국어 음성은 기기마다 있을 수도 없을 수도 있음 → 없으면 효과음만 (FR-08b). 갤럭시는 보통 삼성/구글 TTS 한국어가 기본 탑재, Windows는 "한국어 음성 팩" 설치 여부에 따라 다름 → 시작 화면에서 음성 유무 확인

## 5. 기술 방향 (제안)

| 선택지 | 장점 | 단점 | 판단 |
|--------|------|------|------|
| **웹 앱(PWA) 하나로 두 플랫폼** | 코드 하나, 설치 간단(홈 화면 추가), 오프라인 가능 | 시스템 키 차단 한계 (4장) | ✅ **MVP로 권장** |
| 안드로이드 네이티브 + Windows 네이티브 | 잠금 기능 가장 강력 (Lock Task 모드 등) | 코드 두 벌, 개발량 많음 | ❌ |
| PWA + 나중에 데스크톱/안드로이드 래퍼 | MVP 코드를 재사용하면서 잠금만 강화 | 래퍼 빌드·배포 부담 | 🔜 MVP 이후 필요하면 |
