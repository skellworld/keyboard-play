# 스파이크 결과 — 고장난 키보드 입력 측정

> 측정일: 2026-11-21 · 도구: [spike/keylog.html](../spike/keylog.html) · 원본: `spike/results/*.json` (로컬 전용, 커밋하지 않음)

## 결론
- **키보드는 정상 키보드로 취급한다** (사용자 결정, 2026-11-21). 측정 중 고장 증상이 사실상 나타나지 않았다.
- 채터링 필터·멈춘 키 처리·키업 유예 같은 **고장 대응 전용 기능은 뺀다**. 자동반복 무시, 초당 생성 제한, 화면 객체 상한은 **아이가 손바닥으로 연타하는 상황** 때문에 그대로 유지한다.
- Windows Chrome에서 **Keyboard Lock이 Esc(짧게)와 Alt+Tab을 막는 것을 확인**했다. Esc를 길게 누르면 전체화면이 풀리는 것도 확인 → 일시정지 오버레이(FR-25)가 반드시 필요하다.
- **태블릿은 측정하지 못했다** → 7단계 실기기 검증에서 확인 (리스크 R5 유지).

## 측정 환경
| 항목 | 값 |
|------|-----|
| 기기 | Windows PC + 고장난 키보드 (USB) |
| 브라우저 | Chrome 157 (localhost → 보안 컨텍스트) / Claude 앱 내장 브라우저 |
| 측정량 | 약 4분, 키 누름 약 290회 (자동반복 제외) |

## 1. 입력 안정성
| 지표 | 결과 | 해석 |
|------|------|------|
| 같은 키 120ms 안 재입력 | 2회 / 약 290회 (105ms, 108ms) | 사람이 빠르게 두 번 친 수준. 고장 신호(보통 30ms 이하)는 없음 |
| 떼지 않았는데 또 눌림 | 0회 | 정상 |
| 사람의 가장 빠른 같은 키 연타 | 128ms | 120ms 필터였다면 정상 입력을 버렸을 것 → 필터 제거가 맞음 |
| 키 떼고 다시 누르기 최소 간격 | 54ms | 정상 |
| 누른 시간 | 최소 20ms, 중간값 약 136ms | 정상 |
| `event.code` 이상값 (`Process`, 229, 빈 code) | 0회 | 한글 IME 영향 없음 (입력창 없이 받으면 정상) |

## 2. Ctrl + Alt + P 3초 누르기
| 회차 | 결과 |
|------|------|
| 1회 | 끊김 없이 **3.95초** 연속 유지 ✅ |

→ 정상 키보드이므로 **키업 유예(FR-34) 불필요**. 단, 창 포커스를 잃으면(blur) 누름 상태를 초기화한다.

## 3. 전체화면 · 시스템 키 (Windows Chrome, Keyboard Lock 켬)
| 동작 | 결과 | 비고 |
|------|------|------|
| 전체화면 / Keyboard Lock / Wake Lock | 모두 성공 | localhost(보안 컨텍스트) |
| Esc 짧게 (~100ms) ×6 | ✅ **막힘** — 전체화면 유지, 페이지가 Esc 키를 받음 | |
| Alt+Tab ×4 | ✅ **막힘** — 페이지가 Alt·Tab을 받고 창 전환 없음(blur 없음) | |
| Esc 길게 | ⚠️ **약 1.5초 후 전체화면 해제** (3회 재현: 1.55s, 1.54s, 1.55s) | 브라우저 보안 정책, 변경 불가 → FR-25 |
| Win 키 | ❓ 미확인 (잠금 상태에서 Win 키 이벤트 기록 없음) | 7단계에서 재확인 |

## 4. 읽어주기 음성 (PC)
- 한국어 음성 2개: **Microsoft Heami** (기기 내장), **Google 한국의** (온라인)
- "기역, 에이, 일" 재생 확인 → 오프라인에서는 Microsoft Heami 사용

## 5. 미측정 항목 → 7단계로 이관
- [ ] 갤럭시 태블릿 + 키보드: `event.code` 정상 여부, 뒤로/Esc/홈 키 동작, 한국어 음성 유무
- [ ] Windows 잠금 상태에서 Win 키
- [ ] Edge 브라우저 동작 (Chrome과 같은 엔진이라 동일할 것으로 예상)
